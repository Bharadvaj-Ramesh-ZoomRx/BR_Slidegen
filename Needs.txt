 **Rationale for why validated analysis contains data but not the slide generation**
 Excellent question — and it exposes the real issue.

  source_data.json DOES have the data. That's exactly how validated_analysis.md got its numbers — the Stage 3 insight writer read source_data.json directly
  and pulled every value it needed.

  The gap isn't in the data. The gap is in Stage 5 — the config scaffolder.

  scaffold_config_from_plan() tries to auto-generate extraction YAML by matching question codes from the slide plan against the _codes index. It fails and
  falls back to mocks when:

  - Code format mismatch — slide plan says Q1.85b but _codes has C1_85BZ
  - Segment columns — HII vs Others or Academic vs Community require row_range with specific col_map pointing to columns 9/10, 13/14, etc. — the scaffolder
  doesn't know which columns are which segments
  - Impact module — questions on the TP2 & MS module or NPP sheets may not have been fully mapped
  - Derived metrics — geometric mean ME, SOV calculations, scorecards that combine data from multiple question codes

  So it had the data right there, but couldn't auto-wire the extraction config — and instead copy-pasted the numbers from validated_analysis as mock
  literals.

  This means the fix is more straightforward than I initially framed it. We can use source_data.json (already fully indexed) to build proper extraction
  configs for each mock, rather than manually hunting through the Excel. Want me to start?
